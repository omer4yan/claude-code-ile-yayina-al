My learning journey

7 modules 40 lessons Claude Code ile Yayına Al

Here you can see the course's seven modules and 40 lessons in one place. Each lesson has its own page: a step-by-step walkthrough, a simulated terminal you can try in your browser, and a listen option.

Scroll down to browse a module's lessons; click a lesson's name to start it. The lesson content is based on my lesson notes; at the end of each module I also noted the main idea that stuck with me.

My journey Module 01

Install Claude Code

First steps in the terminal

6 lessons34 min read

I started the course by getting to know the terminal. The first exercises were done in a practice terminal running in the browser; this is where I learned to ask which folder I was in, list its contents, and create a new project folder and move into it.

Lessons

  1. 1Terminal, in your browserA first project folder in the browser's practice terminal with pwd, ls, mkdir and cd.8 min
  2. 2Your first fileAsking Claude for a hello.txt file, then verifying the result with ls and cat.6 min
  3. 3Where did that file go?The idea of a working directory; where files are saved, and moving up one folder with cd ...6 min
  4. 4When Claude gets it wrongStopping with Esc, undoing with /rewind, stating what you observed and what you expected, and starting over with /clear if needed.6 min
  5. 5What Claude is allowed to doReading the approval screen, permission modes and the scope of an "always allow" permission.5 min
  6. 6Module 1 summaryThe location, request, check mental model and a quick reference of the basic commands.3 min
Start the module
What stuck with me

Location, request, check: first I know where I am, then I say clearly what I want, and finally I check the result myself.

My journey Module 02

Your first prompt

Install Claude Code and build your first page

6 lessons31 min read

In this module I installed Claude Code on my own computer and, with my first real prompt, created a one-page website called index.html. What I really learned, though, was how a good request is put together.

Lessons

  1. 1Anatomy of a promptInstalling Claude Code on Windows, a first index.html and the "where, what, why" template.7 min
  2. 2The clarity leverNaming the file and the property instead of making a vague request; asking for suggestions first when unsure.6 min
  3. 3Context windows and /clearWhat context is; the difference between /clear and /compact.5 min
  4. 4Slash commands/clear, /compact, /rewind, /help, /model, /init and /exit.5 min
  5. 5@file and @directoryPointing to the right file or folder with @ and using context sparingly.5 min
  6. 6Module 2 summaryPrompts that are specific about the task and sparing with context.3 min
Start the module
What stuck with me

Look before you leap: if I'm not sure, I first ask for a review and suggestions; then I choose which change to make.

NextModule 03 — Single-file edits
My journey Module 03

Single-file edits

Read the diff, decide, check the result

5 lessons17 min read

In this module I learned to read what a change will do before approving it. Every proposed edit is an offer; accepting, adjusting or rejecting it is my decision.

Lessons

  1. 1Reading a diff- and + lines; scanning a large diff by file, scope and what is being removed.5 min
  2. 2Accepting and adjusting editsAccepting a proposal, adjusting it with short feedback or rejecting it.3 min
  3. 3Asking for explanationsHaving the file and the proposed change explained before changing anything.2 min
  4. 4Small refactorsTidying up code without changing how it looks; moving colours into CSS variables.5 min
  5. 5Module 3 summaryAsk → read the diff → accept or adjust → check the page.2 min
Start the module
What stuck with me

Ask → read the diff → accept or adjust → check the page. The smaller the change, the easier it is to review.

NextModule 04 — Build a multi-page site
My journey Module 04

Build a multi-page site

Plan, spread across pages, review the whole

5 lessons14 min read

Once a site has more than one page, a change affects other files too. In this module I learned to ask for a plan before editing and to break the work into small, checkable pieces.

Lessons

  1. 1Why planning mattersAsking for a plan with a file list and an order before editing; plan mode.4 min
  2. 2Edits across filesAdding a shared menu consistently to every page and testing the links.4 min
  3. 3Breaking tasks into piecesSplitting big work into natural steps and stopping to review after each one.2 min
  4. 4Reviewing your own diffGoing through the whole site; checking completeness, consistency, links and real content.2 min
  5. 5Module 4 summaryPlan → change → review the diff → check the pages.2 min
Start the module
What stuck with me

Plan → change → review the diff → check the pages. Before saying "done", you have to actually look at the result.

NextModule 05 — Ship your first project
My journey Module 05

Ship your first project

From your computer to the internet

6 lessons11 min read

The files on my computer don't open on anyone else's screen. In this module I learned the basic workflow for moving a site from local files to a public web address.

Lessons

  1. 1Localhost vs. the live webThe difference between file://, localhost and a public HTTPS address.2 min
  2. 2Git: the five commands you needinit, add, commit, remote add and push; descriptive commit messages.2 min
  3. 3Deploying to VercelConnecting a GitHub repository to a host; checking the file name and path when you get a 404.2 min
  4. 4Environment variables and secretsKeeping secrets out of the code and the repository; replacing a leaked key.2 min
  5. 5Domains, HTTPS and really going liveRegistering a domain, A and CNAME records, HTTPS and the "stranger's tour".2 min
  6. 6Module 5 summaryCommit → push → verify the deployment → check.1 min
Start the module
What stuck with me

Commit → push → verify the deployment → check the live site. These skills are less about memorising commands and more about understanding what each step does.

NextModule 06 — Hooks, MCP and workflow
My journey Module 06

Hooks, MCP and workflow

Structure the way you work

6 lessons11 min read

This module was the move from giving one-off requests to organising the way I work. The common goal was to make the right information permanent and to reduce repeated work with the right tool.

Lessons

  1. 1CLAUDE.md: teach Claude your projectWriting down the project, how to run it, preferences and boundaries in a permanent instruction file.2 min
  2. 2Slash commands and subagentsSaving a frequent request as a command; handing a large task to a focused helper.2 min
  3. 3Hooks: automate the boring partsAutomations that run a command on a specific event, and testing them.2 min
  4. 4MCP: give Claude new toolsConnecting to external tools and data sources with the least access needed.2 min
  5. 5Beyond the terminal: Agent SDKMoving a workflow that has been verified by hand into a program.2 min
  6. 6Module 6 summaryMoving repetition to the right place: a project note, a command, an automation or a connection.1 min
Start the module
What stuck with me

Move repetition to the right place: if information repeats, put it in a project note; if a request repeats, make it a command; if mechanical work repeats, turn it into a tested automation.

The goal of the last module was to plan and publish a small site that can actually be used and shared with others. Everything I had learned in the previous modules came together here.
